## Autonomy root-cause fix (2026-07-26) — why nextech10 needed human rescue

Asked directly: did NexSidi fully deliver nextech10, or did a human intervene? Honest answer at the
time: a human intervened — I hand-fixed code, hand-fixed the live database, and manually re-drove
the pipeline's internal functions from a script after the real Temporal workflow got stuck and
escalated to `needs_review`. This section is the root-cause fix for *why* the autonomous run
couldn't close itself out, found by going back to the actual mechanism rather than assuming.

**Root cause, found by reading the code, not guessing:** in both places NexSidi's pipeline attempts
self-repair — `pipeline/orchestrator/stages/stage5-qa-fix-loop.ts` (QA fix-and-retest) and
`stage6-deployment.ts` (post-deploy live-retest fix-and-redeploy) — the fix agent's own
`{success: boolean}` result was discarded:

```typescript
await deps.fixShubham(plan, formatted);   // return value never read
```

When a fix agent genuinely fails to complete — exhausts its own iteration budget, hits an
unrecoverable model error — the code is left **unchanged**. The loop had no way to distinguish that
from "the fix ran but didn't fully resolve the issue," so it spent a full stuck-detection window (2
QA re-scans, each 3 full agent passes + peer debate at Stage 5; a full docker redeploy + live-retest
