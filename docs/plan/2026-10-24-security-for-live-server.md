# Security work for the live server (kept separate, 2026-10-24)

Found in the live check of 2026-10-24 (docs/root-cause/2026-10-24-brewline.md, section 8). Each item says what was
seen, what to do, and how to prove it is done. Nothing here was changed yet, by decision.

**One item matters before the live server, on this laptop:** A1. The dev stack is reachable from the Wi-Fi the laptop is
on (network profile "Public"). Recreating the containers takes about a minute and loses nothing.

| # | Finding (seen 2026-10-24) | Fix | Proof that it is done |
|---|---|---|---|
| A1 | The running dev containers listen on every interface: Temporal 7233, Temporal UI 8088, Redis 6379, Postgres 5434. `docker-compose.dev.yml` already says 127.0.0.1, but the containers were created before that and never recreated. The network profile is Public and Docker Desktop has an inbound allow rule for Public. Redis answers without a password; Temporal has no login. | Recreate the dev containers from the compose file; add a Redis password (`--requirepass`, `REDIS_URL` with the password). On the live server: no Temporal/Redis/Postgres port open to the internet at all; Temporal Cloud or mTLS. | `docker ps` shows `127.0.0.1:` for every port; `redis-cli ping` without the password answers `NOAUTH`; a port scan from another machine finds nothing open. |
| A2 | Agent commands run directly on the host (`run_command` spawns on the host; allowed: node, npx, npm, bun, curl, git). The container sandbox covers only the type check and verification commands. A checker's sub-check used this to run `node update.js` and change a database. | Run every agent command in the existing container sandbox (`NEXSIDI_SANDBOX_BUILDS`, patent claim 5) with only the project folder mounted and no network except the app's own containers; on the live server this is mandatory. | A test agent command cannot read `E:/ai yug/keys`, `.env`, or reach an outside host. |
| A3 | `GOOGLE_APPLICATION_CREDENTIALS` (the key file path) is passed to agent commands; the block list is a deny-list, so any new secret passes. | Switch to an allow-list of environment variables for agent commands (PATH, NODE_ENV, the project's own ports and test values only). | The env of a test agent command contains only allow-listed names. |
| A4 | Secrets in logs and model text: the deploy summary "Updated JWT_SECRET to …" (6 times in Brewline's pipeline.log, also saved in the conversation history and sent to the model). The cause — a new secret on every deploy — is fixed (batch 24); old logs still hold values. | Redact values of `*_SECRET`, `*_PASSWORD`, `*_KEY`, connection strings and bearer tokens in agent summaries, logs and saved histories; delete or redact existing logs before the server move. | Grep of all build logs and saved histories finds no secret value. |
| A5 | `update.js` and `verify.js` (left by the checker's sub-check) in Brewline's project folder, each with the database connection string and password. The cause (sub-checks could write) is fixed (batch 17). | Delete the two files; the delivery step refuses to ship any file not produced by a builder (list of files written by builders vs the folder). | The files are gone; a test with a stray file blocks delivery. |
| A6 | `/api/pipeline/:id/retry` checks sign-in but not that the project belongs to the caller. | Same owner check as the other project routes (`projectAccessGuard`). | A test: another user's Retry answers 403. |
| A7 | A second Google project as a rate-limit fallback was offered. On pay-as-you-go a 429 is shared-pool contention, not a project quota, so it adds no capacity; Google's API terms forbid circumventing usage limits; the first project was flagged once. | Do not rotate projects. For more capacity: Provisioned Throughput or Priority PayGo (paid), or a quota request. | — |
